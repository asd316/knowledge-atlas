# 术语表

这份术语表定下项目里每个名词的唯一叫法。文档、代码、界面文案都以此为准。

## 1. 结构：内容怎么组织

| 术语 | 代码名 | 定义 | 例子 |
|------|--------|------|------|
| **图谱** | `atlas` | 所有知识包合并之后得到的整张网络 | 就是整个项目 |
| **知识包** | `pack` | 一个可以独立添加或移除的内容单元，带有自己的领域、条目、联动和声明。主体内容本身也是一个知识包 | `core`（主体）、`climate`（气候科学） |
| **大类** | `category` | 最高一级的分组，在 3D 地面上占一块区域 | 技术与生产 |
| **小类** | `cluster` | 大类下的分组，在地面上表现为一簇光柱 | 信息技术 |
| **领域** | `domain` | 一门可以独立学习的学问或行业，是图谱的基本单位 | AI、货币学 |
| **阶段** | `stage` | 一个领域内的发展分期，有起止年份和活跃度（取 1～3） | AI 的“深度学习”阶段 |

> 原来说的“光柱”是领域在 3D 视图里的**画法**，不是数据概念。写数据时说“领域”，描述画面时说“光柱”。

## 2. 内容：图谱里有什么

| 术语 | 代码名 | 定义 |
|------|--------|------|
| **条目** | `entry` | 图谱里任何一个可以点开阅读的知识点。下面五种类型都是条目 |
| **条目类型** | `kind` | 条目的种类，决定它的画法和泳道 |
| **里程碑** | `milestone` | 改变领域走向的事件，只有一个年份 |
| **著作** | `work` | 书、论文、报告 |
| **人物** | `person` | 有生卒年份，画成竖条 |
| **思想** | `idea` | 概念、理论、方法 |
| **辩论** | `debate` | 有正反两方（`sides`）和持续时间的争论 |
| **联动** | `link` | 跨越**两个领域**的事件，说明一个领域怎样影响了另一个。内容分三段：背景、经过、后果 |
| **关联** | `relation` | 条目之间的一条边，例如“作者”“提出”“反驳”。不需要单独写说明 |
| **驱动力** | `driver` | 联动属于哪一类推动，取 `tech`（技术）、`cap`（资本）、`policy`（战争或政策）、`idea`（思想）之一 |
| **归属** | `domains` | 条目属于哪些领域。一个条目可以属于多个领域，例如凯恩斯同时属于经济学和货币学 |

两条约定：

- **联动和关联不能混用。**
  - 联动连接的是**领域**，本身就是一个条目，有标题，有三段说明。
  - 关联连接的是**条目**，只是一条带标签的边。
- **人物、著作只保留一份。** 同一个人在多个领域出现时，是同一个条目带多个归属，而不是每个领域各写一份。目前 `detail.js` 里的凯恩斯、李嘉图、弗里德曼都各有两份，迁移时要合并。

## 3. 时间

| 术语 | 代码名 | 定义 |
|------|--------|------|
| **时点** | `point` | 只有一个年份 `y` 的条目，包括里程碑、著作、思想 |
| **时段** | `span` | 有起止年份 `y`～`y2` 的条目，包括人物、辩论。结束年份为空表示至今 |
| **时代** | `era` | 全局的历史分期，横跨所有领域 |
| **冲击** | `shock` | 同时波及许多领域的单一事件，例如 1929 年的大萧条 |
| **前史** | `prehistory` | 1760 年以前的源头，只写一段文字，不上时间轴 |
| **时间切片** | `slice` | 用一个年份去截所有领域，查看当时的状态 |

## 4. 视图：怎么看

| 术语 | 代码名 | 定义 |
|------|--------|------|
| **全局视图** | `global` | 3D 场景，所有领域的光柱和联动光弧 |
| **领域视图** | `domain` | 进入单个领域，展开成泳道 |
| **泳道** | `lane` | 领域视图中的一列，每条泳道放一种条目类型 |
| **出口** | `portal` | 领域视图右侧通往其他领域的联动，点击可以跳转 |
| **图谱视图** | `graph` | 平面的力导向网络，所有条目和关联都画出来，类似 Obsidian 的图谱 |
| **局部图谱** | `local graph` | 只显示以某个条目为中心、N 步以内的邻居 |
| **待补条目** | `stub` | 被引用了但还没写说明的条目，例如一条里程碑提到了某人，但这个人还没有人物条目。在图谱中画成空心点 |

## 5. 扩展：怎么加新内容

| 术语 | 代码名 | 定义 |
|------|--------|------|
| **清单** | `manifest` | 知识包的头部信息：`id`、名称、版本、依赖 |
| **依赖** | `requires` | 本包引用了哪些包的内容，例如气候科学包依赖 `core` |
| **放置** | `placement` | 新领域放在哪个大类、哪个小类下，可以放进已有的，也可以新建 |
| **领域模板** | `template` | 一组可以复用的设置，例如有哪些泳道。模板可以继承另一个模板 |
| **类型扩展** | `kind extends` | 知识包自定义新的条目类型，从 `point` 或 `span` 继承画法 |
| **补丁** | `patch` | 知识包向别的包里已有的条目追加归属或关联，但不改写原文 |
| **全局 ID** | `pack:id` | 跨包引用时使用的完整 id，例如 `core:ec-p-keynes`。在同一个包内部可以省略前缀 |

## 6. 不再使用的叫法

| 旧叫法 | 改为 | 原因 |
|--------|------|------|
| 节点（node） | **里程碑**；泛指时说**条目** | “节点”在图谱视图里指所有点，会产生歧义 |
| 连线（link，指跨领域的那种） | **联动** | 和图谱里普通的“边”区分开 |
| 细节（detail） | **条目** | `detail.js` 只是文件名，不是概念 |
| 任务 | **人物** | 原话是笔误，已经确认 |
| 光柱（在数据里） | **领域** | 光柱只是画法 |
