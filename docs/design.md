# 设计说明

这是当前实现（v2）的设计记录，供后续重新设计时参考。

## 1. 两个视图

### 1.1 全局视图

**空间布局**

时间沿竖直方向（Y 轴）向上：1760 年在地面，今天在顶部。

层级在地面上逐级聚拢：
- 每个领域是一根光柱。
- 同一小类的光柱聚成一簇。
- 同一大类的几簇占据地面上的一块区域。

| 元素 | 画法 | 含义 |
|------|------|------|
| 光柱 | 分段圆柱体，加光晕 | 一段对应一个发展阶段，粗细表示活跃度（`heat` 取 1～3） |
| 节点 | 发光精灵，加核心小球 | 关键事件，`w` 表示重要度 |
| 跨领域连线 | 二次贝塞尔光弧，上面有流动的粒子 | 两个领域之间的联动；粒子流动方向表示影响方向 |
| 时代分层 | 半透明轮廓平面 | 历史分期，对应 `eras` |
| 冲击平面 | 红色平面 | 1929、1945、1973、2008 这几个大冲击 |
| 时间切片 | 底部滑块控制的切面 | 查看某一年各领域的截面状态 |

**连线类型**（`kinds`）

| 类型 | 颜色 |
|------|------|
| 技术推动 | `#5eead4` |
| 资本推动 | `#facc15` |
| 战争或政策推动 | `#fb7185` |
| 思想影响 | `#e2e8f0` |

**时间刻度**

刻度是非线性的，越靠近现代展开得越宽：`yH(y) = H · ((y − 1760) / 266)^1.45`，其中 `H = 120`。

**交互**
- 悬停任意元素：高亮它。
- 点击：在右侧面板显示详情。
- 选中一个元素后：其余内容变暗（`focusSet()`）。
- 左侧：层级树。
- 搜索：节点、连线、领域都能搜。
- 图例：可以按连线类型开关显示。
- 标注模式：在“仅关键点”和“全部标注”之间切换。
- 视角按钮：3D、俯视、时间正视。

### 1.2 领域视图（泳道）

进入方式有三种：
- 双击一根光柱。
- 在面板里点“进入领域视图”。
- 在搜索中选中某个领域条目。

进入后，选中的那根光柱展开成五条泳道，时间轴按这个领域自己的起止年份重新铺开。刻度指数是 1.15，高度 `HD = 150`。

| 泳道 | 颜色 | 画法 |
|------|------|------|
| 里程碑 | 领域色 | 点，来自全局视图的节点 |
| 经典著作 | `#fbbf24` | 点 |
| 人物 | `#c4b5fd` | 竖条，从出生画到去世，能看出谁和谁同时代 |
| 思想 | `#7dd3fc` | 点 |
| 辩论 | `#f9a8d4` | 粉、蓝两根并行的竖条，分别代表争论双方；长度是争论持续的时间 |

视图里还有这些元素：
- **左侧粗柱**：沿用全局视图中的阶段和活跃度。
- **白色细线**：领域内条目之间的关联（`rel`）。
- **右侧出口**：跨领域的连线不展开对方领域的内容，只画一小段线，末端是一个对方领域颜色的光环。
  - 点线段：在面板里阅读这条联系。
  - 点光环：跳转到对方领域。
- **条目面板**内容：
  - 说明
  - 辩论双方的主张
  - 直接相关的条目
  - 同一时期的其他条目
  - 同一时期的跨领域出口
  - 在同一泳道里翻看上一条或下一条
- **返回**：点“返回全局”或按 Esc。按 Esc 时，先清除选中，再退出领域视图。

## 2. 视觉风格

- 深色单主题（`color-scheme: dark`）。
- 发光效果用加法混合（additive blending）实现。
- 三个大类的主色：

  | 大类 | 颜色 |
  |------|------|
  | 技术与生产 | `#38bdf8` |
  | 经济与资本 | `#fb923c` |
  | 人与社会 | `#a78bfa` |

- 标签是 HTML 覆盖层：每一帧从 3D 坐标投影到屏幕位置，按优先级贪心剔除互相重叠的标签。
- 布局：顶栏、左侧树（236px）、舞台、右侧面板（380px）、底部时间轴。
- 窄屏（宽度小于 860px）：
  - 左侧树改成抽屉。
  - 右侧面板改成底部抽屉，最大高度 34vh。
  - 相机自动拉远：`narrowK` 取 1.25 或 1.5。

## 3. 技术实现

- 库：Three.js r128（UMD 版，从 cdnjs 加载）和 OrbitControls（从 jsdelivr 加载）。没有构建步骤。
- 页面：`src/index.html` 一个文件，按 claude.ai Artifact 页面格式编写，不含 `<html>`、`<head>`、`<body>` 标签，CSS 和 JS 都内联在里面。
- 数据：`src/data.js`（全局视图数据）和 `src/detail.js`（领域视图细节）分开存放，通过 `<script src>` 引入。
- 状态：
  - `S.layer` 表示当前视图，取值 `'global'` 或 `'domain'`。
  - `S.dom` 是当前所在的领域。
- 场景组织：全局视图的对象都在组 `G` 里，进入领域视图时隐藏这个组。
- 路由：`refresh`、`pick`、`select` 三个函数先看当前视图，再分发到对应的处理逻辑。

## 4. 已知问题与可改进方向

- `index.html` 将近 90KB，全局视图和领域视图的代码混在一起，适合拆成模块，并引入构建工具。
- 数据直接以 JS 全局变量的形式定义，可以考虑改成 JSON 或 YAML，并加上 schema 校验。
- 节点和连线的引用没有自动校验，例如连线指向了不存在的领域 id。
- 目前没有自动化测试，只有 `tools/screenshot.js` 用于截图检查。
- 手机端可以用，但没有专门设计过。
- 其余 15 个领域还没有细节数据。
