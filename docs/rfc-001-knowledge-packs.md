# RFC-001 知识包：让新领域像插件一样接进图谱

- **状态**：草案，已有可运行的原型（`src/atlas-core.js`、`src/packs/climate.js`、`src/graph.html`）
- **术语**：见 [glossary.md](glossary.md)

## 1. 要解决的问题

以后学一个新领域，就算它不在现在这 19 个领域里，也要能沿用现有的做法：
- 同样有阶段、里程碑、著作、人物、思想、辩论。
- 同样能和已有领域连起来。

学得越多，这些领域连起来，最终形成一张大网络。

现在做不到，原因有三个：

1. 所有内容写死在 `data.js` 和 `detail.js` 两个文件里。加一个领域，要同时改好几处。
2. 条目的 id 没有命名空间。两个人各写一份内容，id 可能冲突。
3. 同一个人物在不同领域各写一份。凯恩斯在经济学和货币学里各有一份，网络在他身上是断开的。

## 2. 方案

### 2.1 一个领域或一组领域 = 一个知识包

```
src/
  atlas-core.js          注册表：加载、继承解析、合并、校验
  data.js  detail.js     主体（自动包装成 id 为 core 的知识包）
  packs/
    climate.js           Atlas.pack({...})
    philosophy.js        以后新学的领域，每个一个文件
```

页面按顺序加载：主体，然后 `atlas-core.js`，然后各个知识包。之后调用 `Atlas.build()`，得到合并好的整张图谱。

### 2.2 知识包的结构

```js
Atlas.pack({
  id: 'climate', name: '气候科学', version: '0.1.0',
  requires: ['core'],                       // 依赖哪些包

  kinds:     { report: { extends: 'point', name: '观测与报告', color: '#86efac' } },
  templates: { science: { extends: 'discipline', addLanes: ['report'] } },

  categories: [{ id: 'nature', name: '自然与环境', color: '#4ade80',
                 clusters: [{ id: 'earth', name: '地球系统', domains: ['climate'] }] }],
  placement:  { /* 或者把领域放进已有小类：climate: { cluster: '国际秩序' } */ },

  domains: { climate: { name, desc, pre, template: 'science', stages: [[1824, 1957, '发现温室效应', 1], ...] } },
  entries: [ { id: 'p-keeling', k: 'person', y: 1928, y2: 2005, t: '查尔斯·基林', x: '…', rel: ['m-1958'] }, ... ],
  links:   [ { id: 'x-fossil', a: 'energy', b: 'climate', y1: 1880, y2: 1958, drv: 'tech', t: '…', bg, what, out } ],
  patches: [ { target: 'core:ec-p-coase', addDomains: ['climate'] } ]
});
```

### 2.3 “继承”放在哪里

“插件类继承”在这里体现为**声明式继承**，不用 JS 的 class。知识包只放数据，不放代码，这样任何人或任何 agent 都可以放心地写，写错了也只会在数据检查里报警告。

| 继承什么 | 怎么写 | 得到什么 |
|----------|--------|----------|
| **条目类型** | `kinds.report = { extends: 'point' }` | 新类型自动获得父类型的时间形态（时点或时段）、画法和泳道行为 |
| **领域模板** | `templates.science = { extends: 'discipline', addLanes: [...] }` | 继承父模板的全部泳道，再追加自己的 |
| **知识包** | `requires: ['core']` | 可以引用被依赖包里的领域和条目，可以给它们打补丁 |

内置的继承树：

```
point（时点，抽象）── milestone 里程碑 · work 著作 · idea 思想 · （climate 包里的）report 观测与报告
span （时段，抽象）── person 人物 · debate 辩论 · link 联动
discipline 学科模板 ── （climate 包里的）science 自然科学模板
```

如果以后确实需要行为扩展，例如某个领域要用特殊画法，再在模板上加一个可选的 `render` 钩子。第一版不做。

### 2.4 ID 与引用

| 规则 | 说明 |
|------|------|
| 包内 id 随便写 | 例如 `p-keeling` |
| 全局 id = `包id:条目id` | 例如 `climate:p-keeling`、`core:ec-p-keynes` |
| 引用不写前缀，就先在本包里找 | `rel: ['m-1958']` |
| 跨包引用必须写前缀 | `rel: ['core:ec-p-samuelson']` |
| 领域 id 是全局唯一的短名 | 例如 `climate`、`energy`，冲突时报错 |
| 条目不写 `d` 时 | 归入本包的默认领域（包里只有一个领域时，就是那一个） |

### 2.5 合并规则

1. **同名合并**：类型相同、标题相同的人物或著作合并成一份。归属取并集，关联取并集，说明保留较长的那份，并记录合并了哪些 id。
2. **名字解析**：里程碑和联动里的 `p`（人物名）、`bk`（书名）会被解析成指向条目的边。
   - 人物名先按全名匹配，再按“·”后面的姓氏匹配。同姓有多个人时不按姓氏匹配。
   - 解析不到的名字生成**待补条目**（stub）。
3. **补丁**：只能给别人的条目追加归属和关联，不能改写原文。

### 2.6 数据检查

`Atlas.build()` 返回 `issues`，以下情况会报出：

- 重复 id
- 引用不存在的领域或条目
- 依赖的包没有加载
- 继承成环
- 模板不存在
- 一个小类超过 3 个领域（3D 视图每簇最多排 3 根光柱）

页面会在控制台打印这些问题。以后可以把同样的检查做成 `node tools/check.js`，放进 CI。

### 2.7 和现有 3D 页面的关系

为了不重写 3D 页面，`Atlas.applyLegacy()` 会把合并结果写回旧格式的 `window.ATLAS` 和 `window.ATLAS_DETAIL`。代价是：

- 3D 领域视图仍然只有四条固定泳道。自定义类型会退回到最近的内置祖先显示：`report` 显示在“思想”泳道。
- 3D 页面里，合并过的人物仍按原来的方式在每个领域各显示一次。

下一步应该让 3D 页面直接读 `Atlas.build()` 的结果，泳道改为由模板决定。

## 3. 图谱视图（graph.html）

在 3D 视图之外，新增一个平面的力导向网络，类似 Obsidian 的图谱。

| 元素 | 画法 |
|------|------|
| 大类、小类、领域 | 带光晕的大点，作为骨架；可以关掉 |
| 条目 | 实心点，大小取决于关联数和重要度 |
| 联动 | 空心环，连到两个领域，颜色表示驱动力 |
| 待补条目 | 空心点 |
| 关联 | 细线；悬停或选中时，邻居高亮，其余变暗 |

可用的操作：

- **局部图谱**：只看选中条目周围 1 步或 2 步以内的内容。
- **着色**：按领域，或按条目类型。
- **筛选**：按条目类型、知识包、是否显示待补条目、是否显示骨架。
- **截至年份**：拖动滑块，或点“播放生长”，看网络从 1760 年开始一步步长出来。
- **总览面板**：列出“连接最多的条目”和“最常被提到、还没写的”。后者就是一份按重要性排好的学习待办清单。

## 4. 以后新学一个领域的流程

1. 复制 `src/packs/climate.js`，改成 `src/packs/<新领域>.js`。
2. 决定放置位置：放进已有小类，或者新建大类和小类。
3. 先写阶段和 5～8 个里程碑，再写人物、著作、思想、辩论。
4. 写 3～6 条联动，连到已有领域。人物名、书名尽量和已有条目保持一致，这样合并会自动发生。
5. 在 `index.html` 和 `graph.html` 里加一行 `<script src="packs/<新领域>.js">`。以后可以改成从 `packs/index.json` 自动加载。
6. 打开图谱视图，检查控制台里的数据检查结果，再看“最常被提到、还没写的”列表，决定下一步补什么。

## 5. 待决定的问题

1. **知识包的文件格式**：现在是 JS（`Atlas.pack({...})`），好处是不用 fetch，直接用 `<script>` 加载就行。要不要改成 JSON 或 YAML，再加 schema 校验？
2. **主体要不要拆**：主体要不要拆成 19 个小包，每个领域一个？拆开之后贡献和审阅更方便，但主体里跨领域的联动要找地方放。
3. **人物要不要独立成“人物库”包**：这样所有领域都只引用人物，不再定义人物，可以彻底消除重名问题。
4. **3D 视图的布局**：图谱变大以后，3D 视图要不要只显示选中的大类？
